# 极端故障测试报告（2026-10-20）

## 测试范围

本轮针对“断电、断网、进程崩溃、状态文件损坏、客户端异常断开、上传中断”做本机故障演练。
为避免把整台机器或局域网真的切断，采用等价的本机故障注入：

| 场景 | 注入方式 |
|---|---|
| 突然断电 | 用 `TerminateProcess` 强杀 `mobile_web.py` / ComfyUI 主进程，不执行正常退出 |
| 断网（后端） | 强杀 ComfyUI，让网页服务失去唯一的本机执行器 |
| 断网（客户端） | TLS 连接发送半截 HTTP 请求后立即断开；60 个并发正常请求 |
| 磁盘/断电写坏状态 | 把 `jobs_state.json`、`queue_control.json`、`monitor.json`、`teams.json`、`team_prompts.json`、`cleanup.json`、`sessions.json`、`users.json` 写成非法 JSON 后重启 |
| 上传中断 | 自定义节点 ZIP 只上传一半就强杀网页服务 |
| 全机断电 | 同时强杀网页服务和 ComfyUI，再同时冷启动 |

没有执行真实关机、没有禁用网卡/防火墙规则，避免影响这台机器和热点网络。

## 发现并修复的问题

### 1. ComfyUI 中断时任务会挂 15 分钟
原逻辑每 2 秒请求一次 `/history`，连接失败只 `continue`，直到 900 秒总超时才结束。
期间任务一直显示 running，调度槽位被占用，新任务无法提交。

修复：
- `/history` 请求超时从 60 秒改为 5 秒；
- 连续 6 次连接失败（约 22 秒）直接标记“ComfyUI 连接中断”，释放槽位；
- 若 ComfyUI 重启后内存队列清空，运行中任务在 `/queue` 里连续 5 次找不到，
  标记“ComfyUI 已重启或丢失该任务”，不再无限等待。

### 2. `users.json` 损坏可能退回旧密码/默认管理员
原来解析失败会把 `USERS` 当成空，再回退 `access.json`；如果 `access.json` 不存在，
就可能出现 `admin/admin`。

修复：
- 每次保存账号前，把上一份可解析的 `users.json` 复制为 `users.json.bak`；
- 启动时主文件损坏会自动读 `.bak`；
- `.bak` 已加入 `.gitignore`、发布包和离线包的排除列表，不会泄露密码哈希。

## 仍然存在的限制

- 没有做真实 UPS 断电和物理网线/网卡断开；进程强杀已经覆盖了“突然消失”的主要代码路径，
  但真实断电还可能造成 NTFS 延迟写入、文件系统损坏，需要靠备份和 UPS 解决。
- 没有做磁盘写满、目录 ACL 拒绝写入的测试；相关写盘失败目前都会被捕获，但不保证
  所有第三方 ComfyUI 节点都能优雅处理。
- 强杀网页服务时，ComfyUI 仍可能把已经提交的图跑完，留下一个不在图库里的孤儿输出文件；
  这是“服务端失联”的固有限制，不会重复交付，但需要手动清理 `ComfyUI/output`。
- 真实手机在热点断开/重连后的浏览器行为没有在本轮模拟；浏览器端已有轮询和断线重试，
  但建议在手机上再手动验证一次。
- 本轮没有验证第二台 worker 在断电/断网时的表现；worker 协议已有心跳和超时重排，
  需要真实第二台机器才能做完整验收。
