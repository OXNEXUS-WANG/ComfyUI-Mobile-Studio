# LoRA 训练说明

网页版在 v1.2.0 加入 LoRA 训练：普通账号提交项目，管理员审核，训练在本机
GPU 上执行；训练期间本机出图自动暂停，训练结束后恢复。

训练组件不随发布包分发，第一次使用需要管理员在网页里一键安装。

---

## 1. 硬件和底模

| 项目 | 要求 |
|---|---|
| 显卡 | NVIDIA，支持 CUDA；Anima 8GB 显存可跑 |
| 内存 | Anima 建议 16GB；SDXL 建议 24GB 以上 |
| 磁盘 | 训练器约 200MB，数据集和检查点另算；默认至少保留 3GB |
| Python | 使用安装目录自带的 Python 3.13，不额外安装 |

| 训练类型 | 状态 | 说明 |
|---|---|---|
| **Anima 2B** | **推荐** | 8GB 显存可用；默认 768、block swap 22；先缓存 latent/文本后约 3 秒/步 |
| **SDXL** | 实验性 | 仅 Illustrious / Juggernaut 等 epsilon 模型；本机 8GB/16GB 实测加载 U-Net 时 OOM。低于 11GB 显存或 22GB 内存会直接拒绝提交，建议 12GB+ / 24GB+ |
| NoobAI v-pred | 未验证 | 默认隐藏；管理员在训练设置里打开 `allow_sdxl_vpred` 才可选 |
| RealVisXL Lightning | 不推荐 | 蒸馏模型，不作为训练底模列出 |

Anima 需要以下三个文件（安装器/模型下载里已有）：

```text
ComfyUI/models/diffusion_models/anima-aesthetic-v1.1.safetensors
ComfyUI/models/text_encoders/qwen_3_06b_base.safetensors
ComfyUI/models/vae/qwen_image_vae.safetensors
```

SDXL 训练还需要 `ComfyUI/models/vae/sdxl-vae-fp16-fix.safetensors`。

## 2. 管理员第一次安装训练组件

1. 用管理员账号打开网页，进入 **训练** 标签。
2. 页面上方会出现「训练组件」卡片，点 **安装训练组件**。
3. 安装器会从 `gh-proxy.com` 下载固定 commit 的 kohya sd-scripts，
   校验 ZIP 大小和 SHA256，然后安装最小依赖到 `trainer/pysite`。
4. 安装完成后自动运行健康检查：Python、torch、CUDA、diffusers、accelerate、
   transformers、`networks.lora_anima` 都必须通过。
5. 显示「就绪」后，在训练设置里打开 **启用训练**。

安全边界：

- 只使用固定 HTTPS 下载地址和固定 commit，不跟随上游 master；
- pip 使用 `--no-deps --require-hashes`，**不会安装/升级 torch、transformers**；
- 训练器完全位于 `trainer/`，不修改 ComfyUI 的 `site-packages` 或 `_pth`；
- 安装失败会保留旧版本并显示日志尾部，不会把半成品当成可用组件。

安装后 `trainer/` 约 200MB。卸载会把 `sd-scripts`、`pysite` 移到
`trainer/_uninstalled_<时间戳>/`，保留现场，不会直接删除。

## 3. 管理员设置与审核

训练设置（训练标签内的管理员区）：

- **启用训练**：总开关，默认关闭。
- **需要审核**：默认开启；关闭后普通账号提交即批准，但仍受资源和配额限制。
- **允许的训练类型**：Anima / SDXL。
- **训练时间窗口**：可限制在夜间，例如 01:00–07:00。
- **等待策略**：只等当前本机任务结束，不取消已排队任务。
- **资源阈值**：Anima/SDXL 最低空闲显存、最低可用内存、最低磁盘、最高 GPU 温度。
- **单项目上限**：图片数、数据集体积、步数、轮数、分辨率。
- **取消权限**：普通账号是否可取消自己的训练。
- **SDXL 模型白名单 / v-pred 解锁**。

审核流程：

1. 用户提交后项目进入 **待审核**，不会占用 GPU。
2. 管理员在训练标签的待审核卡片查看底模、图片数、步数、预计时长。
3. **通过** 需要二次确认，可设置优先级和最长运行分钟；**拒绝**必须填写原因。
4. 通过后项目进入训练队列，等待窗口、训练器、资源、配额全部满足才启动。
5. 管理员可随时强制停止；运行中的训练不会因为用户退出页面而中断。

普通账号默认关闭「LoRA 训练」功能。管理员可在 **后台 → 用户管理** 单独开启，
并设置每日训练次数、每月训练分钟、单次上限、最大步数、数据集张数和大小、
最大分辨率、是否允许视频/放大/挂机等。

## 4. 用户训练流程

1. 打开 **训练 → 新建训练**。
2. 填写名称、训练类型、底模、触发词（建议英文，例如 `mychar`）和默认描述。
3. 选择预设：角色 / 画风 / 快速测试；参数可再调整。
4. 创建后进入详情，添加训练图片：
   - **上传图片**：支持多选；服务端按 4MB 分块接收；
   - **从图库选择**：只会复制并重新编码，不会影响原图。
5. 每张图可以单独写 caption；留空时使用「默认描述 + 触发词」。
6. 点 **提交审核**。
7. 管理员通过后等待训练；页面会显示排队位置、显存/内存等待原因、进度、
   loss、速度和预计剩余时间。
8. 完成后可以下载 LoRA，或点 **在出图中使用** 跳到文生图并自动选中底模和 LoRA。

数据集要求：

- 每个项目至少 5 张，默认最多 100 张（还受账号配额限制）；
- 只接受 PNG/JPEG/WebP，服务端会用 Pillow 真正解码、摆正 EXIF、转 RGB、
  重新编码并剥掉原始元数据；
- 损坏、伪装、超大图、动图会被拒绝；
- 图片和 caption 保存在 `trainings/<账号>/<项目>/dataset/`。

---

## 5. 训练期间资源怎么分配

训练和出图共用同一块显卡，系统按以下顺序让路：

1. 项目被批准后只是排队，不影响出图。
2. 真正启动前设置本机 GPU 闸门，调度器立即停止向本机派发新任务；
   已排队的出图任务保留，不取消；远程 worker 仍可接单。
3. 等待当前本机出图任务结束，调用 ComfyUI `/free` 卸载模型。
4. 检查显存、内存、磁盘、GPU 温度；不达标就进入「等待 GPU」，
   60 秒后自动重试，不会硬启动。
5. 训练进程启动；完成后释放闸门、再次 `/free`，出图自动恢复。
6. 训练期间网页出图/放大/挂机会返回明确的「LoRA 训练占用本机显卡」提示；
   如果配置了可用远程 worker，文生图仍可派到远程。

同一时间只运行一个训练任务。训练是子进程，取消会终止整个进程树，
已保存的检查点保留。

服务重启时：

- 训练进程还活着：按 PID 和启动时间重新接管，闸门保持；
- 进程已退出但输出存在：尝试补发布；
- 进程不在且没有输出：项目标记失败并给出原因。

训练数据、日志和项目状态都在安装目录，不会写进审计日志的提示词正文。

## 6. 参数建议

**Anima 角色 LoRA（默认）**

- 分辨率 768，rank 16，alpha 8，学习率 1e-4，Adafactor，bf16；
- block swap 22（28 层中的 22 层换到内存），H2D-only，ring size 1；
- 5–20 张同一角色、不同角度/表情/服装的图，caption 写角色特征；
- 首次训练建议 800–1500 步；先用「快速测试」512/少量步数确认流程。

**显存/内存不足时**

- 分辨率降到 512 或 640；
- block swap 保持 22，不要盲目调低（调低更吃显存）；
- 关闭 ComfyUI 模型常驻或先让系统 `/free`；
- 减少同时打开的大程序；SDXL 在 8GB 机器上不要勉强。

---

## 7. LoRA 的权限和使用

- 训练产物自动转换成 ComfyUI 的 `diffusion_model.*` 格式，并清除训练 metadata。
- 默认 **私有**：只有训练者本人和管理员能在 `/api/models` 看到并选用。
- 管理员可以 **共享**（所有账号可见）、**分类**（Anima/SDXL 家族）或删除。
- 删除 LoRA 前会检查是否有排队/运行中的任务在引用它；删除会移到回收目录。
- 训练使用的底模在训练期间不能在模型管理里删除。
- Anima 出图支持普通 LoRA；内置的 `anima-turbo-lora-v0.2` 仍作为极速模式内部
  使用，不会出现在普通 LoRA 列表里。

## 8. 文件位置、备份和清理

```text
trainings.json                 项目状态（不含 caption/日志正文）
training_settings.json         全局训练设置
loras.json                     训练 LoRA 归属和共享状态
trainings/<账号>/<项目>/        dataset、dataset.toml、output、logs、train.pid
training_uploads/              分块上传临时文件（自动清理）
trainer/                       sd-scripts、pysite、缓存、安装状态
_training_trash/               删除的项目目录
_lora_trash/                   删除的 LoRA
```

- 备份/恢复工具只带三个训练状态文件（`trainings.json`、`training_settings.json`、
  `loras.json`），**不带** `trainings/` 里的数据集、caption、日志和检查点。
  恢复后旧项目可能仍显示，但缺数据集时不能继续训练；需要手动复制
  `trainings/<账号>/<项目>/`，或重新上传数据集。`trainings/` 在恢复白名单里，
  手动放进备份 ZIP 后可以被恢复。
- 发布包、离线包和公开仓库**不包含**训练状态、数据集、训练器依赖和 LoRA。
- 删除训练项目会把整个项目目录移到 `_training_trash/`，不会动图库原图；
  确认不再需要后可手动清理该目录。

## 9. 常见问题

**训练组件显示「未安装 / 需修复」**

点「安装/修复训练组件」，看安装日志。常见原因是网络无法访问 `gh-proxy.com`
或 pip 镜像；可在训练设置的安装源里换镜像。健康检查失败时不要强行训练。

**一直显示「等待 GPU」**

看卡片上的原因：显存不够、内存不够、磁盘不够、温度过高或前台高负载。
关掉游戏/浏览器/ComfyUI 常驻模型；或把训练时间窗口调到空闲时段。
系统不会在资源不足时硬启动。

**提交时提示硬件不满足**

SDXL 需要至少 11GB 总显存和 22GB 总内存（建议 12GB+/24GB+）。
这台机器请在训练类型里选 Anima 2B。

**训练开始后报内存不足**

16GB 内存对 SDXL/高分辨率 Anima 都很紧。降低分辨率到 512/640，
关闭其他程序，确认 ComfyUI 已 `/free`。Anima 的 block swap 会占用系统内存，
不要同时跑出图。

**训练成功但出图看不到 LoRA**

确认底模家族匹配：Anima LoRA 只能在 Anima 底模使用，SDXL LoRA 只能在 SDXL
底模使用。私有 LoRA 只有本人和管理员可见；需要给别人用请让管理员共享。

**服务重启后训练还在吗**

会。只要训练进程还活着，服务会重新接管并继续显示进度；如果进程已退出，
会按输出补发布或标记失败。不要手动结束陌生的 python 进程，先看训练卡片状态。

**怎么彻底停掉训练**

用户/管理员在训练详情点取消，或管理员在运行中卡片点强制停止。
系统会终止训练进程树、释放 GPU 闸门并恢复出图。已保存的检查点保留。

## 10. 第三方组件和许可

训练使用 [kohya-ss/sd-scripts](https://github.com/kohya-ss/sd-scripts)
（Apache-2.0），固定版本 0.12.2，commit
`11d8cedd0c67b93a10f8b2d75f43554f6f12c794`。Anima 支持来自其官方
`anima_train_network.py` 和 `networks.lora_anima`。训练输出使用官方
`networks/convert_anima_lora_to_comfy.py` 转换成 ComfyUI 格式。

依赖清单和哈希见 `training_requirements.txt`，下载地址和校验见
`training_manifest.json`；许可证汇总见 `THIRD_PARTY_NOTICES.md`。
